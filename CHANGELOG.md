# Changelog

## Unreleased

- The CLI no longer reads `./.env` from the directory it is launched in. A `.env` there belongs to
  whatever project the MCP client started in, and could silently supply or override provider
  keys. Name a file with `--env-file PATH`, or pass variables through the client's `env` block.
  `--no-env-file` is now the default and stays accepted.

## 0.3.0 — 2026-11-26

CiteNexus is now PanCite, published by PanStudio. This release renames every identifier and
adds no aliases for the old names. Tool names, tool behavior and provider IDs are unchanged.

- The PyPI project is `pancite`; `cite-nexus-mcp` receives no further releases. Install with
  `uv tool install pancite==0.3.0` or launch with `uvx --from pancite==0.3.0 pancite`.
- The repository moved to https://github.com/PanStudio/pancite and the official MCP Registry
  name is `io.github.PanStudio/pancite`.
- The `cite-nexus-mcp` and `cite-nexus-wtfp` commands are now `pancite` and `pancite-panwrite`.
- The Python import package `cite_nexus_mcp` is now `pancite`.
- Environment variables use the `PANCITE_` prefix: `PANCITE_CONTACT_EMAIL`,
  `PANCITE_DEFAULT_PROVIDERS`, `PANCITE_TIMEOUT`, `PANCITE_OPERATION_TIMEOUT`,
  `PANCITE_RETRIES`, `PANCITE_CONCURRENCY`, `PANCITE_CACHE_TTL` and `PANCITE_CACHE_SIZE`.
  `CITE_NEXUS_*` variables are no longer read.
- The MCP server name and the server id in the plugin and PanCode pack manifests are `pancite`;
  the plugin bundle moved to `packaging/pancite/`.
- WTF-P is now PanWrite. The companion module is `pancite.panwrite` and its protocol is
  `pancite.panwrite/v1`; each result carries its source record in `pancite` instead of
  `citeNexus`. PanWrite selects it with `--backend=pancite` and finds it through
  `PANWRITE_PANCITE_COMMAND`. WTF-P releases that expect `cite-nexus.wtfp/v1` do not work with
  this release. `scripts/check_wtfp.py --wtfp-root` is now `scripts/check_panwrite.py --panwrite-root`.
- The license changes from MIT to Apache-2.0, with a NOTICE file. Copyright is held by PanStudio.

## 0.2.5 — 2026-11-15

Tool output, descriptions and search relevance tuned after a live WTF-P and Clio run, where a 27B
local model spent about 20K tokens on three searches and misread verification results.

- `search-papers` adds `limit_total`, which caps records across providers, and `detail: "minimal"`,
  which returns id, title, year, the first three authors, venue and DOI/arXiv/PMID and omits
  default-valued fields. The description states that `limit` applies per provider.
- `verify-citation` accepts `identifier` as an alias of `citation`. Results add `match`
  (`identifier` or `metadata`) and `claim_support: "not_checked"`; verification never checks
  whether a paper supports a claim.
- Records without an abstract return `abstract: null` with `abstract_missing_reason`, so callers
  do not infer findings from titles. Searches without `include_abstract` say abstracts were omitted.
- Every tool description includes one example call.
- The `cite-nexus.wtfp/v1` companion request accepts `detail` (`minimal`, `compact` or `full`;
  default `full`) and `limit_total`, passes both to `search-papers`, and echoes them in metadata.
  The default output is unchanged.
- arXiv plain-text queries require every non-stopword term. Previously `all:` applied only to the
  first word and the rest were OR'd, which ranked unrelated multi-agent papers first. Explicit
  field or boolean syntax passes through unchanged.
- `list-providers` and `search-papers` recommend `arxiv` and `semantic_scholar` for
  computer-science queries and state that ordering interleaves provider ranks.
- The README documents a Clio `mcp.yaml` declaration and the plugin-scope
  `clio-coder mcp trust cite-nexus --network` step.

- Fix the installed-wheel distribution check, which expected exactly nine providers and failed on the

## 0.2.3 — 2026-09-23

Add SearchApi.io (`searchapi`) as an alternative commercial provider for Google Scholar discovery, resolution, and citation graphs.

- Add `searchapi` provider adapter accessing `https://www.searchapi.io/api/v1/search` with the `google_scholar` engine.
- Provide a significantly more economical alternative to SerpAPI (~$4/1k queries vs ~$15–$25/1k on SerpAPI) with full parameter and feature parity (`q`, `cluster`, `cites`).
- Support automatic resolution for `scholar:<cluster_id>` identifiers using either `SEARCHAPI_API_KEY` or `SERPAPI_API_KEY`.
- Generalize Google Scholar parser in `commercial.py` to seamlessly normalize both SerpApi and SearchApi.io payload structures (including root-level `authors`, text `publication` summaries, `data_cid` cluster keys, and standard pagination).
- Expose `SEARCHAPI_API_KEY` across configuration, MCP stdio/HTTP servers, tools, and the `cite-nexus-wtfp` bridge companion.
- SerpAPI remains fully supported and unchanged for existing deployments.

## 0.2.2 — 2026-09-17

0.2.1 was merged but never tagged or published; its changes are folded into 0.2.2, the first
release after 0.2.0.

- Report invalid input, unknown providers and provider outcomes as readable tool errors. MCP SDK 2.2
  previously reduced them to "Error executing tool <name>".
- Name the providers that could not find an identifier and suggest search-papers for titles.
- Reject undeclared tool arguments in the input schema (`additionalProperties: false`) and on the
  server, listing the accepted names, so a misnamed `max_results` no longer returns a default page.
- Fix arXiv search and lookup, which failed with HTTP 406 in 0.2.0. arXiv's CDN refuses TLS
  handshakes that offer ALPN without TLS 1.3 post-handshake authentication, which is httpcore's
  default. The HTTP client now enables post-handshake authentication, as Python's `http.client` does.
- Resolve arXiv identifiers through their DataCite DOI (`10.48550/arXiv.<id>`) when arXiv does not
  answer. The record keeps both identifiers and the arXiv issue stays visible as a warning.
- **Default change:** `search-papers` accepts `detail` (`compact` or `full`, default `compact`).
  Compact records return an empty `field_sources`; `sources` still names each provider. Set
  `detail: "full"` for the 0.2.0 record. A default page for three providers drops from 45.4 KB to
  36.7 KB of structured content. The WTF-P companion requests `full`.
- Send tool results as unindented JSON text. The text block previously repeated structured content
  with two-space indentation, 75.0 KB for the same default page; it is now 36.7 KB.

## 0.2.0 — 2026-09-17

CiteNexus becomes a provider-independent scholarly metadata service with public API defaults.

- Migrate to MCP Python SDK 2.2 and protocol 2026-07-28, preserving the legacy protocol path.
- Add typed tools, output schemas, read-only annotations, resources, prompts and progress.
- Add local Streamable HTTP alongside stdio, plus configuration discovery and explicit `.env` loading.
- Add Crossref, DataCite, Europe PMC, arXiv, Semantic Scholar, OpenAlex, Scopus and Web of Science
  Starter alongside the revised SerpAPI integration; add optional Unpaywall enrichment.
- Introduce namespaced identifiers, exact lookup checks, provenance, retained source disagreements,
  version-aware deduplication, native Europe PMC cursor paging and bounded provider requests.
- Add deterministic BibTeX/RIS/CSL-JSON export, citation verification, bounded batch export,
  open-access discovery and citation/reference traversal.
- Correct the citation-count bug: provider totals replace citation-page lengths.
- Remove automatic AI formatting, inferred bibliographic facts and the paid-provider startup requirement.
- Move standalone legacy AI helpers to an optional extra; retain old MCP tool names and SerpAPI aliases.
- Add offline provider fixtures, protocol integration tests, a separate public-API smoke script,
  Python version CI, build configuration and a non-root stdio container definition.
- Rewrite product positioning, configuration, migration and source-access documentation.
- Integrate WTF-P's citation-search workflow through a bounded companion using real MCP stdio;
  preserve candidates and source records, select vendors explicitly, and test timeout cleanup.
- Add `cite-nexus-wtfp --check` and `--no-env-file` for reproducible client-managed configuration.
- Prepare versioned registry and portable/Codex/Claude plugin metadata, a 41-channel marketplace
  inventory, launch copy, icon/social assets, troubleshooting and agent installation guidance.

No release publication or registry registration is performed by this change.
